  Database location:
  ~/Library/Group Containers/9K33E3U3T4.net.shinyfrog.bear/Application Data/database.sqlite

  Key tables (Core Data under the hood, so Z prefixed):
  - ZSFNOTE — all notes, with ZTITLE, ZTEXT (full markdown), ZUNIQUEIDENTIFIER, ZTRASHED, ZMODIFICATIONDATE
  - ZSFNOTETAG — tags, with ZTITLE (e.g. your watch tag)

  Three ways to talk to Bear:
  1. Direct SQLite read (read-only) — best for bulk searching, which is what we'd want
  2. URL scheme (bear://x-callback-url/...) — best for opening/creating notes, which is how we'd send stuff to Bear
  3. Shortcuts — another option but less useful for us

  So we could have it both ways — read from Bear's database to show your #watch items inside Tab Lister, and write to Bear via URL scheme when you want to save a tab with
  notes. We'd never write directly to the SQLite (that would corrupt Bear's Core Data stack).

❯ how can a safari browser extension be added without getting it from the apple store?

⏺ For development and personal use, it's straightforward:

  1. Enable Developer menu in Safari (Safari > Settings > Advanced > "Show features for web developers")
  2. Allow unsigned extensions — in Safari's Develop menu, check "Allow Unsigned Extensions" (you'll need to re-enable this each time Safari restarts)
  3. Build and run the extension app from Xcode — once the app runs, the extension appears in Safari > Settings > Extensions where you toggle it on

  That's it for personal use. No App Store, no Apple review, no signing certificates beyond "Sign to Run Locally" which is what we're already using for Tab Lister.

  If you ever wanted to share it with others outside the App Store, you'd need an Apple Developer account ($99/year) to notarize it. But for your own machine, just build
  and run.
